# ADR 0011: Confine agent runs and check commands with the operating system's sandbox

Status: accepted
Date: 2026-10-12

## Context

Agents write code and the factory runs that code: setup steps, lint, tests, the
frozen acceptance checks. All of it runs on the operator's workstation or a CI
runner, next to credential stores, other projects and the factory's own state. A
check that reads a credential or reaches the network makes the proof unreliable and
the machine unsafe. The factory runs on macOS workstations and on Linux runners.

## Options

1. **No confinement**, trusting reviews. Unacceptable: the reviewer sees the diff,
   not what the code does when it runs.
2. **Containers.** Strong isolation, but a container runtime is a heavy prerequisite
   on a workstation, toolchains must be rebuilt inside images, and the gate would
   no longer run the project's own tooling as its developers do.
3. **The operating system's own sandbox:** `sandbox-exec` profiles on macOS and
   bubblewrap namespaces on Linux, chosen by platform behind one port.

## Decision

Option 3, behind the `CommandSandbox` port, selected by `process.platform`; any other
platform is refused at start with a clear message.

Both adapters enforce the same policy:

- the root file system is readable; writes are limited to the worktree of the issue,
  the temporary directories and the project's configured cache directories;
- the built-in credential stores (SSH, cloud CLIs, `gh`, container registries,
  package registry tokens, the Claude configuration, the keychain) and the project's
  `sandbox.deniedReadPaths` are unreadable;
- the directories of the other projects of the installation are unreadable, so one
  project's run cannot read another's worktrees, evidence or requests;
- the network is off unless a setup step declares why it needs it
  (`network: <reason>`), which the gate records.

On macOS the profile also denies the factory's own listening ports on loopback and
selected executables. On Linux, a command given the network shares the host's
network namespace, so the port filter is not expressible there; bubblewrap's
private network namespace (loopback only) is used for every other command.

Agent runs are confined by Claude Code's own sandbox and permission settings,
generated by the factory with the same deny lists.

## Consequences

- The gate proves behaviour under the same constraints on a workstation and in CI.
- A check that needs the network or writes outside the worktree is rejected as a
  proof, with the refusal named in the before-proof report.
- Linux runners need `bwrap` installed; `agent-factory validate` reports it missing
  as a required tool.
